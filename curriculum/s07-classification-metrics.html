ML Performance Metrics (Classification)

A classification model almost never gets everything right. Today you'll learn to read a confusion matrix and calculate the four numbers everyone quotes — accuracy, precision, recall, and F1-score — and, more importantly, learn why a single accuracy number can quietly hide a model that's dangerously wrong in exactly the way that matters for your system.

1. Why classification needs statistical scoring, not right/wrong

Because ML models are probabilistic and real data is noisy, a classification model will almost never predict every case correctly. Instead of asking "is it correct?", testing asks "how often, and in which direction, is it wrong?" — and the answer to that question is what actually determines whether a model is fit for its purpose. The tool that makes this measurable is the confusion matrix.

2. The confusion matrix: four outcomes, not two

For any binary classification decision, comparing what the model predicted against what was actually true produces exactly four possible outcomes:

True Positive (TP)

Model predicted positive, and it actually was positive. A correct "yes."

False Positive (FP)

Model predicted positive, but it was actually negative. A false alarm — sometimes called a "Type I error."

False Negative (FN)

Model predicted negative, but it was actually positive. A missed case — sometimes called a "Type II error."

True Negative (TN)

Model predicted negative, and it actually was negative. A correct "no."

Every one of the metrics below is built entirely out of these four counts — nothing else.

3. The four core metrics, and what each one actually tells you

MetricFormulaWhat it answers
Accuracy(TP + TN) / (TP + TN + FP + FN) × 100%Of every prediction made, what percentage was correct overall?
PrecisionTP / (TP + FP) × 100%Of everything the model flagged as positive, how much was actually positive? "How much can I trust a positive alert?"
Recall (sensitivity)TP / (TP + FN) × 100%Of everything that was actually positive, how much did the model catch? "How confident am I that nothing positive slipped through?"
F1-score2 × (Precision × Recall) / (Precision + Recall)The harmonic mean of precision and recall — a single number that stays low if either one is weak, unlike a simple average.
⚠
Accuracy alone is the most dangerous metric to trust blindly Accuracy treats every correct prediction the same, whether it's a TP or a TN — which means it can look excellent on a heavily imbalanced dataset (e.g. a rare disease, or rare fraud) while the model is essentially useless at the thing you actually care about. The lab below makes this concrete: you'll see two models with the same accuracy whose real-world behavior couldn't be more different.

4. When precision matters more than recall — and vice versa

Recall matters most when missing a positive is costly

Medical screening for a serious disease: a false negative means a sick patient is told they're fine. Teams deliberately accept more false positives (more people get sent for a follow-up test that turns out negative) to avoid missing real cases.

Precision matters most when a false alarm is costly

Spam filtering: a false positive means a real, important email gets buried in the spam folder. Teams deliberately tolerate a few spam messages slipping through (more false negatives) to avoid ever hiding a legitimate email.

There is no universally "correct" balance — the acceptable trade-off between precision and recall is a product/business decision informed by the real-world cost of each error type, and it should be captured as part of the acceptance criteria defined back at "understand the objectives" (Session 5).
