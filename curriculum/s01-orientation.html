1. Why AI-based systems need a different kind of tester

Conventional software is built from explicit rules: a developer writes if / then / else logic, and given the same input, the program always produces the same output. Testing that world means comparing actual output to one correct expected output.

Most AI-based systems — especially anything built on machine learning (ML) — don't work that way. Instead of following hand-written rules, they learn statistical patterns from training data and apply those patterns to new, unseen inputs. That single shift breaks several assumptions traditional testing relies on:

There's often no single "correct" answer.

Ask an LLM to summarize a paragraph and there are many acceptable summaries. Testing has to shift from exact-match assertions toward statistical evaluation, acceptable error rates, and quality thresholds.

The model can be a black box.

A neural network can have billions of internal parameters. You often can't read the "logic" the way you'd read source code — you have to test behavior from the outside, in.

Systems can keep changing after release.

An adaptive system that keeps learning in production can drift away from the behavior you originally validated — testing becomes an ongoing activity, not a one-time gate.

The data is part of the system under test.

Bad training data produces a bad model no matter how good the code is. An AI validation engineer tests data, the model, and the surrounding pipeline — three surfaces instead of one.

This is the core of the discipline you're building over the next 26 sessions: everything from here on is about how to adapt sound testing principles — risk-based thinking, coverage, oracles, test levels — to a system that behaves probabilistically instead of deterministically.

💡
Mental model to keep You already know how to test. What's new is where uncertainty enters the system (data → model → pipeline) and how you set a pass/fail bar when "correct" is a probability, not a boolean.

2. What you'll be able to do by the end

This training is built for testers, test analysts, data analysts, test engineers, and technically-minded managers who need to work with AI-based systems — whether or not you ever sit a certification exam. By the end, you should be able to:

  • Explain the current state of AI, including generative AI, in plain terms.
  • Get hands-on experience building and evaluating a simple machine learning model.
  • Explain how a simple neural network works and how it can be tested.
  • Apply the AI-specific quality characteristics used to judge whether an AI-based system is "good."
  • Calculate and interpret the standard performance metrics used to score ML models.
  • Recognize the two test levels unique to machine learning systems, and why both matter.
  • Contribute to a test strategy for a machine learning system.
  • Design and run real test cases against a machine learning system.

3. How the curriculum is structured

Rather than spend equal time on every topic, this training weights each subject by how much it actually matters to a competent AI validation engineer — not by how long it takes to read about. To ground that weighting in something rigorous rather than just my opinion, it borrows the scope and emphasis of an internationally recognized body of knowledge for AI testing (the ISTQB Certified Tester AI Testing syllabus) — the same one training providers and certification bodies use. 4. How this course is built

30 sessions, Monday–Friday only

About one hour each, roughly 6 calendar weeks. Weekends are yours. Topic areas are weighted by real-world importance — Machine Learning (Sessions 5–10) gets 6, Model Testing (17–20) gets 4, ML Development Testing (21) gets 1.

Every lesson ends with a quiz

Instant feedback, worked explanations, and your score is saved locally so the dashboard can track your progress across the whole course.

Hands-on labs, not just reading

Interactive simulators you can drag, tune, and break: a confusion-matrix calculator, a perceptron trainer, a metamorphic-testing relation builder, a red-teaming sandbox, and more.

Everything runs offline

No external links to click out to, no CDNs, no video files to download. Diagrams and animations are built directly into each page.
